🧠 REMEMBER THIS

A website has a skeleton, clothes and muscles.

Day 3 simplified the three core web technologies using an easy mental model.

H

HTML = Skeleton

HTML provides the structure. Headings, paragraphs, buttons, images and sections begin here.

C

CSS = Clothes

CSS controls presentation. Colours, spacing, typography, layout and visual styling live here.

JS

JavaScript = Muscles

JavaScript adds behaviour. It helps buttons, interactions and dynamic features actually work.

🚨 RULE ZERO

Your homepage needs the right name.

A tiny naming mistake can stop your website from behaving the way you expect. The class emphasized one filename you should remember: index.html

❌ DON'T DO THIS Index.html INDEX.HTML homepage.html

Computers care about exact names. Small differences can matter.

✅ REMEMBER THIS index.html

Lowercase. Exact spelling. This is the standard homepage filename used in the Day 3 deployment workflow.

🐙 BUILD YOUR DIGITAL LAND

From an empty repository to a live project.

GitHub may look technical at first, but the classroom workflow can be remembered as a simple sequence.

01

Create your GitHub account

Your account becomes the identity from which your repositories and projects are managed.

02

Create a new repository

Think of the repository as the digital space that will hold the files of your website.

03

Add index.html

Create the main website file and keep its name exactly index.html.

04

Paste your generated code

Take the website code created with AI and place it inside the correct file.

05

Commit the changes

Save the changes in the repository so GitHub has the latest version of your project.

06

Enable GitHub Pages

Use the repository's Pages settings to publish the project as a website.

🌐 DEPLOYMENT MEMORY

Repository ≠ Website until you publish it.

Saving code on GitHub and publishing that code through GitHub Pages are connected steps, but they are not the same thing.

📁

Repository

Stores the files and versions of your project.

🚀

GitHub Pages

Publishes the website so it can be opened through a web address.

🎯 DAY 2 → DAY 3

C-T-F now becomes a building tool.

The prompting framework from Day 2 can now be applied to website creation. Better instructions give AI a clearer picture of what it needs to build.

C

Context

Explain what the website is for, who will use it and the overall purpose of the project.

T

Task

Tell AI exactly what it should build: the sections, features, interactions and content you need.

F

Format

Specify the expected output, such as a complete mobile-friendly HTML file ready to copy and paste.

💬 THINK LIKE AN ARCHITECT

Don't just say: “Make me a website.”

Describe the digital experience before asking AI to construct it.

❌ WEAK INSTRUCTION Make a website for me.

The objective is too broad. AI has to guess the audience, sections, style and functionality.

✅ ARCHITECT MINDSET

Tell AI the purpose of the website, the target audience, required sections, desired experience and the exact output format you need.

⚙️ THE ZERO-CODE WORKFLOW

Prompt. Copy. Paste. Deploy.

This is the practical loop that turns your AI conversation into something people can actually open on the web.

01 • PROMPT

Explain Your Vision

Give AI enough context and clear requirements for the website.

02 • COPY

Take the Code

Copy the generated HTML/CSS/JS carefully without accidentally cutting parts of the code.

03 • PASTE

Put It in GitHub

Paste the code into the correct repository file and commit it.

04 • DEPLOY

Publish With Pages

Enable GitHub Pages and turn your stored project into an accessible website.

05 • TEST

Open the Website

Check the page on mobile and desktop. Test buttons, links, images and layout.

06 • IMPROVE

Return to AI

Describe what needs changing, update the code and deploy the improved version again.
